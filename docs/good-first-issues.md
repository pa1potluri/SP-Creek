# Good first ideas — draft only

These ten ideas are suggestions for lead review, not published issues or instructions to start work. The lead must choose the allowed files and check for overlap with the queue before assigning one.

1. **Clearer freeze-button help.** Add a short tooltip explaining that freezing pauses world time while the picture stays visible. Keep the icon and keyboard behaviour. Check the tooltip with mouse and keyboard, and confirm freeze/resume still works.
2. **Preset duration labels.** Show the total minutes beside each ready-made video. Calculate from its clip durations without changing preset IDs. Check a short episode and a long background preset, including wrapping on a narrow panel.
3. **Friendlier empty timeline.** Explain how to choose a preset or add a first clip when the timeline is empty. Keep existing controls usable. Check empty, one-clip and reopened projects.
4. **Readable range-control values.** Give one small group of sliders consistent value labels and useful accessible names. Preserve their ranges and saved values. Check keyboard changes and project save/load.
5. **A gentle flower-pot variation.** Add one rounded colour variation to an existing approved pot, without another plant species or collision shape. Use a seeded choice. Compare the same location in day/night and Oil/Film.
6. **A clearer local project filename.** Suggest a friendly SP Creek name when downloading a project. Preserve its JSON format and import compatibility. Reopen the downloaded file and verify the scene and timeline.
7. **Accessible style descriptions.** Add one short description per existing style so newcomers know what each changes. Label Watercolour as a preview and keep Animated film the default. Check all styles and the narrow panel.
8. **A tidy screenshot index.** Make a small Markdown index for one completed task's day/night and Oil review images. Use existing local files and relative links; do not regenerate or publish anything. Check every link resolves.
9. **A quiet bench-name label.** Improve one existing Build catalogue label so a child or parent can recognise the piece. Keep its internal type and saved layouts unchanged. Place, save, reopen and delete that piece.
10. **A missing-art fallback note.** Document how an existing optional painted asset falls back in the local studio, using one approved example. Do not remove private assets or invent licensing claims. Verify the documented path and check the fallback without starting sound.

Every accepted implementation follows [CONTRIBUTING.md](../CONTRIBUTING.md): child-safe scope, full suite, required screenshots, result file and local commit. No issue is posted by this draft.
